為什麼攤銷時間複雜度是 O(1)？｜Why amortized O(1)?

在容量加倍模型中，擴充時搬移的元素數依序為 1、2、4、8、16……。執行 n 次 append，搬移總量小於 2n；加上 n 次新元素寫入，總成本小於 3n，因此每次操作的攤銷成本為 O(1)。

With doubling capacity, total copying over n appends is less than 2n, and new writes cost n. Thus total cost is O(n), and amortized cost per append is O(1).

3. 學習重點｜Key Takeaways

單次最差 / Worst Case: O(n) — 擴充容量時，必須搬移既有元素。
When resizing, existing elements must be copied into a larger array.

攤銷 / Amortized: O(1) — 將一連串 append 的總成本分攤至每次操作。
Spread the total cost of many append operations across those operations.

教學注意 / Teaching Note: 這是「容量每次加倍」的簡化教學模型，並非 CPython list 實際使用的擴充比例。CPython 的容量增長策略不同，但 append() 仍具有攤銷 O(1) 的特性。
This is a simplified doubling model, not the actual CPython list growth policy. Python list append still has amortized O(1) complexity.
